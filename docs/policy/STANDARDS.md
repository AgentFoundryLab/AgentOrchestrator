# Project Technical Standards

**Version**: 1.1.0 | **Updated**: 2026-02-24
> Amend with rationale. Bump: MAJOR (breaking), MINOR (additions), PATCH (clarifications).

## Platform

- Runtime targets: Claude Code, Codex, Gemini, OpenCode, and Qwen (bash + markdown/JSON/TOML installer outputs — zero Python dependencies for package)
- Shell scripts MUST use `#!/bin/bash` and `set -e`
- Python scripts MUST use uvx shebang (`#!/usr/bin/env -S uvx --from <pkg> python`) and run directly (`./script.py`), never via `python script.py`
- Required tools: `bash`, `jq` (for JSON merging in `install.sh`)

## Source of Truth

- Skill instructions MUST live in `package/skills/<skill>/SKILL.md` — agents are thin wrappers only
- Policy source MUST live in `package/policy/` — deployed to `<runtime-root>/policy/`; `docs/policy/` is project-generated output, not package source
- Agent definitions MUST live in `package/agents/` — YAML frontmatter + markdown body
- Templates MUST live in `package/templates/` — deployed at install time, not hand-authored in output dirs
- `docs/INDEX.md` is the canonical directory map — generated by `/onboard`, referenced by `AGENTS.md`

## Runtime Contracts

- Runtime native capability and installer scope MUST be documented separately; they are not interchangeable

## Naming

- Skill dirs: `package/skills/<skill>/SKILL.md`; agent files: kebab-case (`business-analyst.md`)
- ADR files MUST use the tier-scoped id as filename: `docs/architecture/ADR/ADR-<TIER>-NNN.md`
- Record documents MUST be named for their id: `FRD-<SCOPE>-NNN.md`, `FBP-<TIER>-NNN.md`, `WO-NNN.md`, `ISS-NNN.md`, `REG-NNN.md`, `TD-NNN.md`, `PLAN-NNN-<slug>.md`
- Index files MUST use SCREAMING_SNAKE_CASE: `STANDARDS.md`, `WORKORDERS.md`, `REQUIREMENTS.md`, `ISSUES.md`, `TECH_DEBT.md`
- Hook scripts MUST use kebab-case with `.sh` suffix

## Commit Conventions

- Commits MUST use Conventional Commits format: `type(scope): message`
- Observed types: `feat`, `fix`, `docs`, `refactor`
- Feature branches MUST be created; direct commits to `main` are not permitted

## Security

- No secrets in skill, agent, or hook files
- API keys MUST use environment variables
- `.serena/` MUST be excluded from git (transient Serena memory data)
- Deployer agent MUST run in `permissionMode: plan` — destructive operations require user approval
- `disallowedTools` MUST be set on agents where write/edit access is inappropriate (Validator: no Write/Edit; Deployer: no Edit)
