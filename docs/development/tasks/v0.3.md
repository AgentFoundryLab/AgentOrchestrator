## v0.3: Installer Redesign (Bash → Python)

### T-115: Write ADR-015: installer redesign from bash to Python
**Milestone**: v0.3
**Depends on**: v0.2.0 complete
**AC**:
- ADR at `docs/architecture/adr/015-installer-python-redesign.md`
- Context section documents current bash installer pain points: no unit testability, global state via env vars, no type safety, fragile string manipulation, no package-level dependency management
- Decision: Python package (`orchestrator-install`) installable via `uvx`/`pipx`
- Alternatives considered: keep bash + BATS, rewrite in Node.js, rewrite in Go
- Migration path documented: bash installer remains until Python parity; cutover gated on T-120 CI green
- Python toolchain choice justified (e.g. `typer` for CLI, `tomllib`/`tomli-w` for TOML, `ruamel.yaml` for YAML round-trip)

---

### T-116: Design Python installer module decomposition
**Milestone**: v0.3
**Depends on**: T-115
**AC**:
- Module decomposition doc at `docs/architecture/installer-decomposition.md`
- Package layout defined: `orchestrator_install/` root, `cli.py` (entry point), `dispatcher.py`, `runtimes/` (one module per runtime), `lib/` (shared utilities)
- Each runtime module interface specified: `install(ctx)`, `uninstall(ctx)`, `check(ctx)` with typed `InstallContext` dataclass
- Shared lib contract specified: `transforms` (frontmatter, settings merge), `validation` (schema checks, path drift), `utils` (idempotent write, backup/restore)
- CLI flag contract maps to current `install.sh` flags (no user-visible regression)
- Module dependency graph documented: runtimes depend only on `lib/`; no sibling runtime imports

---

### T-117: Bootstrap Python installer package
**Milestone**: v0.3
**Depends on**: T-116
**AC**:
- `pyproject.toml` at repo root (or `installer/pyproject.toml`): package name `orchestrator-install`, entry point `orchestrator-install = orchestrator_install.cli:app`
- `uvx orchestrator-install --help` runs cleanly listing all flags
- `uvx orchestrator-install --check` runs dispatcher stub and exits 0 with version + runtime matrix stub output
- Runtime dispatcher stubs wired: each runtime module loaded dynamically, no-op on call
- `install.sh` thin shim preserved: delegates to `uvx orchestrator-install "$@"` with fallback warning if Python unavailable

### T-118: Implement runtime-scoped Python modules
**Milestone**: v0.3
**Depends on**: T-117
**AC**:
- `orchestrator_install/runtimes/claude.py`, `codex.py`, `gemini.py`, `opencode.py`, `qwen.py` each implement `install(ctx)`, `uninstall(ctx)`, `check(ctx)`
