# ISS-006: Runtime target isolation across global installs

> Root-cause work item. Carried forward from `I-006`; see `../ID-MAP.md`.

## Classification

- Category / scope / type: `bugfix` / `installer` / `config`
- Severity: `High`
- Root-cause state: `Confirmed`
- Root cause: global install paths were resolved from a shared root rather than per-runtime, so an install or uninstall scoped to one runtime reached another's artifacts.

## Status

`Closed` — the isolation defects were addressed in the runtime-decoupling work. Its remaining symptom, the Gemini command-transform failure, was extracted as `REG-002` and reclassified under `ISS-002`, whose root cause owns it.

## Links

- Affected requirements: `TRC-006.2`, `TRC-006.3`
- Related Work Order: `WO-097`
- Linked reports: none remaining — `REG-002` moved to `ISS-002`

## Diagnosis

Three distinct symptoms shared one cause — path resolution that was not runtime-scoped:

- `install.sh --global --overwrite --codex` touched shared `~/.claude/*` paths.
- `install.sh --global --overwrite --gemini --uninstall` removed `~/.claude/*` without `--claude`.
- Policy references in non-Claude context docs pointed at `@~/.claude/policy/*`.

A fourth reported symptom — Gemini emitting command files its own loader rejects — turned out to be a transform defect, not an isolation defect. Keeping it here would have made this issue symptom-shaped, so it was extracted rather than fixed under a cause that does not explain it.

## Remediation

Runtime-scoped path resolution throughout the installer, with conformance tests asserting that an operation on one runtime leaves every other untouched. Landed; `TRC-006.2` covers the invariant.

## Reclassification

`REG-002` was extracted from this issue and relinked to `ISS-002` on 2026-08-13 — the command-transform failure shares the Gemini capability-drift root cause, not this one. This issue keeps its id and its own diagnosis.
