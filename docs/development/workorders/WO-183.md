# WO-183: Anchor delivery on journey outcomes and fail-closed recovery

## Summary

Change the distributed policy, skills, agents, templates, and workflow doc so an orchestrated run is
steered by completed user journeys rather than by closed records. Delivery rigor scales with each
item's risk tier, hydration fails closed, recovery routes by failure class, and shared surfaces have
one integration owner. The evidence is the Cabinet delivery-stagnation analysis
(`docs/analysis/2026-09-28-sdlc-lessons-from-cabinet-delivery-stagnation.md`).

Implementation Plan: [WO-183-implementation-plan.md](WO-183-implementation-plan.md)

## Done When

An agent that reads the installed instruction surfaces meets a rule, at the point where the Cabinet run went wrong, for each of the analysis's failure modes A–G and for the risk-tiered chain. The `$meta-learn` re-validation table records every mode as prevented, reduced, or detected.

## In Scope

- `package/policy/RULES.md`: risk-tier table, readiness verdicts, fail-closed hydration, protected-behaviour minting
- `package/skills/orchestrate/SKILL.md`: risk tier, shared-surface preflight and ownership, scope control, failure-class recovery
- `package/skills/context-compiler/SKILL.md`: fail-closed hydration

## Out of Scope

- A numeric WIP cap. The user rejected it on 2026-09-29.
- Any new record identity field. The risk tier derives from existing fields.
- Engine-specific defects. Those are tracked in `agent-foundry/factory`.
- Migrating existing Work Orders to the new template sections.
