# WO-182: Migrate this repository's artifacts to the record schema

## Summary

Migrate AgentOrchestrator's own 180-plus records from the ad-hoc `FR`/`NFR`/`US`/`T-nnn`/`I-nnn` forms to
the typed record schema, in dependency order, so no commit leaves a dangling id and every historical
reference stays resolvable through a permanent id map.

Implementation Plan: [WO-182-implementation-plan.md](WO-182-implementation-plan.md)

## In Scope

- `docs/development/ID-MAP.md` — the permanent old→new map, authored first
- Requirements: `PRD.md` → `docs/requirements/` `FRD-*`/`TRD-*` + index
- Architecture: `ARCHITECTURE.md` → `FBP-*` blueprints; `adr/` → `ADR/ADR-FND-*` + index
- Plan: `ROADMAP.md` → ordering-only + `PLAN-*`; `BACKLOG.md` → `WO-*` + index + archive index
- Feedback: `ISSUES.md` → `ISS`/`REG`/`TD` records + indexes
- Retiring `PRD.md` and `ARCHITECTURE.md` once their content has moved

## Out of Scope

- The distributed package — `WO-181` owns that
- Re-verifying implementation status; statuses are carried forward with provenance stated, and a `$status-update` pass is a separate item
- Rewriting historical records — ADR originals, `docs/development/tasks/`, and `reports/` keep their old ids

## Requirements

| Requirement | In scope here (brief) |
| --- | --- |
| `REQ-009` | The migrated requirements must be testable and carry their acceptance criteria |
| `REQ-010` | Every requirement must have a traceable path through a blueprint after migration |
| `AC-010.3` | ADRs must become standalone tier-scoped files cross-referenced from their governing blueprint |
| `REQ-011` | Work Orders must cross-reference requirements by id, never by copied text |
| `AC-011.2` | Every migrated Work Order must carry its identity fields |

## Blueprints

- `FBP-FEAT-002` — Record schema and artifact flow: the target model and the one-way citation rule
- `FBP-FND-001` — Package and runtime model: the source-versus-deployed boundary the docs describe

## Test Plan

### Unit Tests

- Every `REQ`/`TR` in the index resolves to a document, and every document's records appear in the index.
- No live artifact retains a pre-migration id form.

### Integration Tests

- Every id cited by a Work Order resolves in the requirements index.
- Every ADR cross-reference resolves to a file that exists.
- The id map covers every old id found in the pre-migration documents.

### E2E Tests

- `bash install.sh --check` and `bash tests/install/smoke.sh` stay green — the migration must not disturb the package.
